# 手机控制（MuMu + phone-mcp）

目标：让一个**纯文本的 AI 也能用安卓手机**——看屏幕、点按钮、打字、刷视频。

---

## 为什么不用 VirtualBox 装 Android-x86

试过，不推荐：

- Android-x86 在 VirtualBox 里显卡/输入/ARM 兼容全是坑
- 没有官方维护，出问题只能自己啃

**MuMu 12 更省事**：

- 自带 adb（`F:\MuMuPlayer\nx_main\adb.exe`），端口 `16384`
- 官方有 `MuMuManager.exe` 命令行，能开/关/多开/装应用/限 CPU
- 兼容性经过大量游戏验证

---

## 一、装 MuMu

1. 官网下载安装（会先下一个小引导器，再拉完整包）
2. 启动一次，让它初始化系统（安卓 15）
3. 记下安装路径，后面要用

**建议设置**（`MuMuManager setting -v 0 -k <key> -val <value>`）：

```
performance_cpu.custom  4       # 4 核
performance_mem.custom  4       # 4 GB
resolution_mode         phone.1 # 手机比例
```

---

## 二、连通 adb

```bash
# 用 MuMu 自带的 adb
F:\MuMuPlayer\nx_main\adb.exe connect 127.0.0.1:16384
F:\MuMuPlayer\nx_main\adb.exe devices
```

应该看到 `127.0.0.1:16384  device`。

> 温度提示：MuMu 重启后 adb 会断，重连一次即可。

---

## 三、装 ADBKeyboard（中文输入必需）

安卓的 `adb shell input text` **不支持中文**，会静默丢字。

1. 下载 `ADBKeyboard.apk`（开源，~17 KB）
2. `adb install -r ADBKeyboard.apk`
3. 启用并设为默认：

```bash
adb shell ime enable com.android.adbkeyboard/.AdbIME
adb shell ime set com.android.adbkeyboard/.AdbIME
```

**坑**：模拟器重启后默认输入法会被重置回系统输入法。

好消息是 phone-mcp 的 `ensureIme()` 会自愈，每次输入前检查一下。
但如果你自己写工具，记得处理这一步。

## 四、装 phone-mcp

```bash
git clone https://github.com/pinganbbOvO/ai-companion-kit
cd ai-companion-kit/packages/phone-mcp
npm install
```

自检：

```bash
set PHONE_ADB=F:\MuMuPlayer\nx_main\adb.exe
set PHONE_SERIAL=127.0.0.1:16384
node src/phone-mcp.js --selftest
```

34 个工具，常用的：

| 工具 | 用途 |
|---|---|
| `phone_screenshot` | 截屏（返回图片，视觉模型能看） |
| `phone_dump` | UI 树 → 可点元素清单（文字+坐标） |
| `phone_tap_text` | **按文字点**（比坐标稳） |
| `phone_tap` / `phone_swipe` | 按坐标点 / 滑 |
| `phone_text` | 打字（中文走 ADBKeyboard） |
| `phone_key` | back / home / recent |
| `phone_macro` | 连招：一串动作重复 N 次 |
| `phone_record_screen` | 录屏抽帧（要 ffmpeg） |

## 五、两个必须打的补丁

上游在**安卓 15 模拟器**上有两个坑，不改就用不了。

### 补丁 1：`uiautomator dump` 段错误

**现象**：`uiautomator dump` 明明把文件写好了，但退出码非 0，phone-mcp 把它当失败，
`phone_dump` / `phone_tap_text` 全挂。

**修法**：把 dump 那一步包进 try，交给后面的 `cat` 判断成败。

```diff
- await shell(`uiautomator dump ${remote}`);
+ // 安卓 15 上 uiautomator 写完文件后会 segfault（退出码非 0），但 dump 是有效的。
+ try { await shell(`uiautomator dump ${remote}`); } catch { /* 文件可能已写好 */ }
```

（有两处：`phone_dump` 和 `phone_tap_text`）

### 补丁 2：截图太大

**现象**：900×1600 PNG ≈ 1.3–2.5 MB，base64 后更大，直接撑爆上下文。

**修法**：返回前压成 JPEG。

```diff
  const bytes = fs.statSync(local).size;
  const content = [{ type: 'text', text: `截图已保存: ${local} (${bytes} 字节)` }];
- if (bytes > 0 && bytes < 4 * 1024 * 1024) {
-   content.push({ type: 'image', data: fs.readFileSync(local).toString('base64'), mimeType: 'image/png' });
+ let imgPath = local, imgMime = 'image/png';
+ if (bytes > 400 * 1024) {
+   const shrunk = await shrinkShot(local);
+   if (shrunk) { imgPath = shrunk; imgMime = 'image/jpeg'; }
+ }
+ if (imgBytes > 0 && imgBytes < 1.6 * 1024 * 1024) {
+   content.push({ type: 'image', data: fs.readFileSync(imgPath).toString('base64'), mimeType: imgMime });
  }
```

`shrinkShot()` 是新增的辅助函数，调用 `voice/shrink-shot.py`。

## 六、判断"看 UI 树"还是"看图"

| 场景 | 用什么 | 原因 |
|---|---|---|
| 系统设置、商店列表、聊天页 | `phone_dump` + `phone_tap_text` | 有可访问性节点，按文字点最稳 |
| 游戏、部分自绘商店 | `phone_screenshot` + `phone_tap(x,y)` | 自绘界面 dump 不到节点，只能看图点 |
| 想确认"点成功了没" | `phone_screenshot` | 一张图胜过十行坐标 |

## 七、别做的事

- **别把它接到装了支付/银行 App 的手机上。** 用模拟器或备用机。
- **别让它无限安装 App。** 要么给白名单，要么在角色卡里写死"装之前先问"。
- 模拟器很慢。点完等 1–2 秒再看，别连点。

## 八、资源占用（4 核 4 GB 配置）

```
空闲     ~2.4 GB 内存，CPU < 5%
刷视频   CPU 10–20%
```

不用就关：`MuMuManager control -v 0 shutdown`，占用归零。
